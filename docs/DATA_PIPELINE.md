# DATA_PIPELINE.md — путь от файла источника до тензора

Статус: **описание того, что работает, плюс спецификация того, чего ещё нет.**
Каждый этап помечен `РАБОТАЕТ` / `ДРЕМЛЕТ` / `ОТСУТСТВУЕТ`.
`ДРЕМЛЕТ` = код написан и покрыт тестами, но не подключён, потому что нет
данных. `ОТСУТСТВУЕТ` = кода нет.

---

## 0. Принципы, которым подчинён конвейер

1. **Сырое не переписывается.** `data/raw/` только читается. Любое
   преобразование пишет новый файл. Иначе провенанс невосстановим.
2. **Каждый этап независимо запускаем и независимо тестируем.** Сплиты,
   признаки, обучение, оценка — отдельные модули с явным контрактом
   (жёсткое правило проекта №4).
3. **Признаки строятся ПОСЛЕ сплита и только по train.** Нарушение этого
   порядка — самая тихая форма утечки, ради измерения которой проект и
   существует.
4. **Отсутствующие данные вызывают ошибку, а не заглушку.** Никаких
   синтетических подстановок в рабочем пути (жёсткое правило №1). Синтетика
   существует ровно в одном месте — `synthetic_fixture.py` — и служит только
   для юнит-тестов; она физически не может попасть в эксперимент, потому что
   загружается другим вызовом.
5. **Фиксированные seed на каждом шаге, где есть случайность:** выбор сплита,
   выборка негативов, инициализация весов, порядок батчей.

## 1. Схема потока

```
data/raw/                      ← только чтение, не редактируется
   drugbank.tab.gz                 191 808 строк, 86 типов    РАБОТАЕТ
   sider/                          5 файлов SIDER 4.1          ЗАБЛОКИРОВАН JOIN
   drugbank_vocabulary/            пусто                       ОТСУТСТВУЕТ
   pubchem/cache, openfda_faers/cache   пустые кэши            ДРЕМЛЕТ
        │
        ▼  (1) загрузка и канонизация
tdc_drugbank.load_raw / load_pairs / load_drugs                РАБОТАЕТ
        │   • канонический порядок пары (drug_a < drug_b)
        │   • схлопывание 406 мультитиповых пар, y_types сохранён
        │   • RDKit: SMILES → канонический SMILES, InChIKey, дескрипторы
        │   • проверка: один DrugBank ID ↔ один SMILES
        ▼
   drugs (узлы) + pairs (положительные рёбра)
        │
        ▼  (2) СПЛИТ — до всего остального
split.build_any(scheme=random_pair | drug | scaffold)          РАБОТАЕТ
        │   • drug: препараты делятся на train/val/test,
        │     пара попадает в бакет по обоим концам → S1/S2/S3
        │   • scaffold: то же, но группировка по каркасу Бемиса–Мурко
        │   • random_pair: делятся ПАРЫ (протекающая схема — объект измерения,
        │     а не рекомендация)
        ▼
   бакеты: train, val_S1..S3, test_S1..S3
        │
        ▼  (3) НЕГАТИВЫ — внутри области соответствующего бакета
assemble.sample_negatives(scheme=uniform | degree_matched)     РАБОТАЕТ
        │   • оба конца негатива берутся из пула препаратов ЭТОГО бакета
        │   • verify_no_negative_is_positive: ни один негатив не является
        │     известным положительным примером — проверяется по ВСЕМУ корпусу,
        │     не только по бакету
        ▼
   supervised dataset: pair, label, bucket, setting
        │
        ▼  (4) ПРИЗНАКИ — обучаемые части фитятся только на train
features.build.build_feature_bundle                            РАБОТАЕТ
        │   • ECFP4 отпечатки (детерминированы, фит не нужен)
        │   • парное кодирование (pair_encoding)
        │   • DDI-граф: рёбра строятся ТОЛЬКО из train-пар (ddi_graph)
        │   • атомные графы молекул (molgraph) → узлы/рёбра для GINE
        │   • страж утечки: ни один не-train бакет не даёт рёбер графу
        ▼
   FeatureBundle
        │
        ▼  (5) ОБУЧЕНИЕ
models.train.Trainer                                           РАБОТАЕТ
        ▼
        ▼  (6) ОЦЕНКА
eval.metrics / paired_stats / calibration / crossval           РАБОТАЕТ
```

## 2. Этап 1 — загрузка

`РАБОТАЕТ` — `src/ddinet/data/tdc_drugbank.py`

Единственный подключённый источник. Ключевые решения и их основания:

- **Схлопывание мультитиповых пар.** 406 неупорядоченных пар имеют более одного
  `Y`. Для бинарной задачи они — одна пара; для типизации — многометочные.
  `load_pairs` схлопывает и сохраняет `y_types`, чтобы ни один взгляд не был
  разрушен.
- **Сохранение ориентации.** `Map` направленный (`#Drug1` — виновник). Мы
  канонизируем порядок для симметричной задачи, но храним `orientations`
  отдельно. Без этого механистический слой был бы невозможен.
- **Проверка «один ID — один SMILES».** Один и тот же DrugBank ID встречается в
  сотнях строк; если бы SMILES расходились, узел графа был бы плохо определён.
  Проверка выполняется, а не предполагается.

`ДРЕМЛЕТ` — `download.py`, `sources.py`: реестр источников с URL, лицензиями и
тем, что каждый даёт. Не подключены, потому что **все биомедицинские хосты
возвращают 403 через прокси** (drugcentral.org, ebi.ac.uk, uniprot.org,
reactome.org, sideeffects.embl.de, api.fda.gov). Данные приносит пользователь.

`ДРЕМЛЕТ` — `drugbank.py`: потоковый парсер full XML (iterparse, плоская
память, обход ловушки с вложенными `<drug>` внутри `<pathway>`). Даёт то, чего
нет в TDC: аннотации CYP450 и транспортёров. Ждёт лицензионный файл.

`ЗАБЛОКИРОВАН JOIN` — `sider.py` + `data/raw/sider/`. Файлы на месте и
целостны (1 430 препаратов, 6 123 термина MedDRA), но SIDER ключуется по STITCH
CID, а корпус — по DrugBank ID и InChIKey. Общего идентификатора нет.
Соединение по названию тоже невозможно: в текущей таблице препаратов колонка
`name` — копия `drugbank_id` (проверено: `(drugs.name == drugs.drugbank_id).all()`
→ `True`), настоящих названий у нас нет. Разблокирует **DrugBank vocabulary**
(CC0): `DrugBank ID → Common name + Synonyms + Standard InChI Key`; парсер
`drugbank.py::parse_vocabulary` уже написан. PubChem PUG-REST (InChIKey→CID)
как обходной путь закрыт прокси.

## 3. Этап 2 — сплит (до всего остального)

`РАБОТАЕТ` — `src/ddinet/data/split.py`

Порядок «сплит → негативы → признаки» не косметика. Если признаки построить
раньше, DDI-граф получит рёбра из тестовых пар, и модель на инференсе увидит
ребро, которое должна предсказать. Это и есть утечка, размер которой проект
измеряет.

Три схемы:

| Схема | Делится | Зачем нужна |
|---|---|---|
| `random_pair` | пары | **протекающая.** Воспроизводит то, что делает большинство публикаций. Не рекомендация — измерительный прибор. |
| `drug` | препараты | честная. Даёт S1/S2/S3: оба препарата видены / один нов / оба новы. |
| `scaffold` | каркасы Бемиса–Мурко | строже drug: близкие по структуре аналоги не расходятся по разные стороны сплита. |

**Страж утечки** (`leakage.py` + проверка в `features/build.py`) сравнивает
рёбра графа со всеми не-train бакетами. Проверка идёт по префиксу имени
бакета, а не по списку имён: ранее список был захардкожен под drug/scaffold и
на random_pair не срабатывал вовсе. Пересечение было измерено до правки и
равнялось нулю — то есть страж был бесполезен, но не ошибочен.

## 4. Этап 3 — негативы

`РАБОТАЕТ` — `src/ddinet/data/assemble.py`

**Негативов в источнике нет.** Все 191 808 строк — положительные. Это не
особенность экспорта, а свойство DrugBank: базы фиксируют, что взаимодействие
есть, и не фиксируют, что его нет. Следовательно негативы генерируются, и
способ генерации — методологическое решение с последствиями для каждого
последующего числа (см. EVIDENCE_MODEL.md §3).

Две схемы, обе прогоняются всегда:

- `uniform` — равномерно из пула бакета. Негативы систематически имеют меньшую
  степень, поэтому задача частично решается одной степенью.
- `degree_matched` — распределение степеней негативов подгоняется под
  положительные. Убирает степенную подсказку, все метрики падают. Это
  **честная** ячейка.

Инвариант области: оба конца негатива берутся из пула препаратов того же
бакета. Иначе тестовый негатив мог бы содержать обучающий препарат и превратить
S3-оценку в S2.

`verify_no_negative_is_positive` сверяется со **всем** корпусом положительных,
а не только с бакетом.

## 5. Этап 4 — признаки

`РАБОТАЕТ` — `src/ddinet/features/`

| Модуль | Что даёт | Обучается на train? |
|---|---|---|
| `fingerprints.py` | ECFP4 | нет (детерминированы) |
| `pair_encoding.py` | разреженное парное кодирование | нет |
| `molgraph.py` | атомный граф молекулы: узлы, рёбра, признаки связей | нет |
| `ddi_graph.py` | граф препарат–препарат | **да, рёбра только из train** |
| `build.py` | сборка `FeatureBundle` + страж утечки | — |

Молекулярный граф не зависит от сплита (структура молекулы — свойство молекулы).
DDI-граф зависит целиком: это и есть место, где утечка возникает у большинства
опубликованных работ.

## 6. Этап 5 — обучение

`РАБОТАЕТ` — `src/ddinet/models/`

Записано здесь, потому что это свойство конвейера, а не модели: обучение
**полнобатчевое**, то есть одна эпоха = один шаг оптимизатора. Первая сетка
Фазы A-2 была признана недействительной именно из-за этого — 150 эпох означали
150 обновлений весов, и модель не могла подогнать даже собственные обучающие
данные. Отсюда два постоянных элемента конвейера:

- **Ворота ёмкости** (`assert_can_overfit`): перед сеткой архитектура обязана
  запомнить малое подмножество (train AUPRC ≥ 0.85 при нулевом dropout). Не
  смогла — сетка не запускается. Это защита от повторения того же класса ошибки.
- **Бюджет шагов, а не эпох**, и `stopped_by` в истории обучения, чтобы
  «остановлено по терпению» и «упёрлось в потолок эпох» не путались.

Подробности и полный разбор эпизода — `docs/FAILURE_CASE.md` §6a и
`docs/PHASE_A2_PROTOCOL.md`, дополнения 9–13.

## 7. Чего в конвейере нет (`ОТСУТСТВУЕТ`)

| Отсутствует | Что разблокирует | Чем заблокировано |
|---|---|---|
| адаптеры мишеней/ферментов | биологическую ветвь модели | нет DrugCentral / DrugBank XML |
| граф путей (Reactome) | механистическое обобщение | 403 через прокси |
| нормализация механизмов по онтологии | предсказание механизма | код черновика есть, требует переписи (MECHANISM_ONTOLOGY.md §6.2) |
| сплит novel × novel | самую строгую оценку OOD | зависит только от нас — следующий шаг |
| ось силы доказательства | эксперимент «качество vs доказательство» | все данные на одном уровне E3 |
| PostgreSQL, фронтенд | — | отложено сознательно |

## 8. Что может обесценить конвейер

1. **Порядок шагов.** Любая перестановка «признаки раньше сплита» ломает всё
   ниже по течению молча. Страж утечки — единственная механическая защита, и он
   проверяет только DDI-граф; кодирование пары он не проверяет.
2. **Схлопывание мультитиповых пар** необратимо для бинарной задачи, если
   `y_types` потеряется при сериализации.
3. **Негативы — наша конструкция.** Любое число зависит от схемы негативов
   больше, чем от архитектуры. Изменится схема — изменятся все выводы.
4. **Единственный источник.** Весь конвейер сейчас питается одним файлом.
   Систематическая ошибка DrugBank становится систематической ошибкой проекта,
   и внутри проекта её обнаружить нечем.
