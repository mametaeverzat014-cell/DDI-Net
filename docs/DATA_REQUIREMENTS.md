# DATA_REQUIREMENTS.md — точный список требуемых данных

Назначение: сказать исследователю **какой файл скачать и какие колонки в нём
нужны**, а не «нужны биомедицинские данные».

Составлено 2026-08-27 на основе реестра `src/ddinet/data/sources.py`, где
источники зарегистрированы с лицензиями и цитированием.

> **Оговорка о проверке ссылок.** Сетевой доступ к биомедицинским хостам из
> среды разработки заблокирован политикой (проверено, HTTP 403). URL взяты из
> реестра и **не проверены на актуальность**. Если ссылка не работает,
> ориентируйтесь на landing page и название файла.

## 1. ПРИОРИТЕТ 1 — DrugBank full database (XML)

**Единственный источник, разблокирующий весь механистический слой.**

| Поле | Значение |
|---|---|
| Название | DrugBank full database release |
| Landing page | https://go.drugbank.com/releases/latest |
| Прямая ссылка | нет — только после входа в аккаунт |
| Лицензия | DrugBank Academic (non-commercial). Бесплатно для академического использования, **требуется одобрение аккаунта**, редистрибуция запрещена |
| Требуемый файл | `full database.xml` (внутри ZIP) |
| Куда положить | `data/raw/drugbank_full/drugbank_full_database.xml` |
| Размер | >1 ГБ в распакованном виде |
| Система идентификаторов | DrugBank ID (`DB#####`) — совпадает с нашим ключом |
| Ожидаемый объём | ~16 000 препаратов, ~1.4 млн утверждений о взаимодействиях |
| Редистрибуция | **ЗАПРЕЩЕНА** — файл в репозиторий не коммитить |

**Требуемые элементы XML:**

| Элемент | Даёт каноническую сущность |
|---|---|
| `<drug><drugbank-id primary="true">` | Drug |
| `<name>`, `<calculated-properties>` → SMILES, InChIKey | Compound |
| `<targets><target><polypeptide>` | Protein, Target, связь `Drug TARGETS Protein` |
| `<enzymes><enzyme>` | Enzyme, связи `SUBSTRATE_OF` / `INHIBITS` / `INDUCES` |
| `<transporters><transporter>` | Transporter, связь `TRANSPORTED_BY` |
| `<carriers><carrier>` | Protein (белки-переносчики) |
| `<drug-interactions><drug-interaction><description>` | сырой текст для маппинга механизма |
| `<pathways><pathway>` | Pathway (частично; покрытие неполное) |
| `<atc-codes>` | грубая фармакологическая категория |
| `<actions><action>` | направление действия: inhibitor / inducer / substrate |

**Потребитель в системе:** гетерогенный биомедицинский граф, mechanism
inference, PK/PD головы.

**Предобработка:** потоковый парсинг (`iterparse`) — целиком в память не
влезет. Парсер существует: `src/ddinet/data/drugbank.py`.

**Риски утечки:** описания взаимодействий и CYP-аннотации происходят из одной
курации. Если pathway-рёбра выводить из тех же аннотаций, из которых получены
метки, задача станет циркулярной. Проверять `features/ddi_graph.py::leakage_audit`
**до** любых выводов.

## 2. ПРИОРИТЕТ 2 — DDInter 2.0

| Поле | Значение |
|---|---|
| Landing page | http://ddinter.scbdd.com/download/ |
| Лицензия | бесплатно для академических исследований |
| Требуемые файлы | `ddinter_downloads_code_A.csv`, `_B`, `_D`, `_H`, `_L`, `_P`, `_R`, `_V` (разбиты по первой букве ATC) |
| Куда положить | `data/raw/ddinter/` |
| Идентификаторы | названия препаратов + DrugBank ID |
| Редистрибуция | не разрешена |

**Требуемые колонки:** `DDInterID_A`, `Drug_A`, `DDInterID_B`, `Drug_B`, `Level`
(Major / Moderate / Minor / Unknown).

**Зачем:** единственный источник **клинической тяжести**. Наша формулировка
«опасные взаимодействия» отображается на `Level = Major`. Без него «опасность»
определить нечем — TDC даёт только тип, не тяжесть.

**Потребитель:** ординальная голова severity, стратификация оценки.

**Парсер:** `src/ddinet/data/ddinter.py`.

## 3. ПРИОРИТЕТ 3 — внешняя валидация

### TWOSIDES

| Поле | Значение |
|---|---|
| Ссылка | https://tatonettilab-resources.s3.amazonaws.com/nsides/TWOSIDES.csv.gz |
| Лицензия | **CC BY 4.0** — качается напрямую, редистрибуция разрешена |
| Даёт | пары + конкретное нежелательное явление + PRR + доверительный интервал |

**Зачем:** TWOSIDES получен из сигналов FAERS, DrugBank — из механистической
курации. Расхождение между ними **научно интересно, а не является ошибкой**:
одно говорит, что фармакологи ожидают, другое — что пациенты сообщили.

### openFDA FAERS

| Поле | Значение |
|---|---|
| Landing page | https://open.fda.gov/apis/drug/event/ |
| Лицензия | public domain |
| Доступ | API, 240 запросов/мин без ключа |

**Критическая оговорка для текста работы:** FAERS — система спонтанных
сообщений. Отчёты не верифицированы, дублируются, смещены вниманием прессы и
**не имеют знаменателя**. Поддерживает анализ диспропорциональности, но не
доказательство причинности. Клиент существует: `eval/faers.py`.

## 5. Чего НЕТ ни в одном из перечисленных

Эти сущности канонической схемы **не покрываются** доступными источниками и
требуют отдельного решения:

| Сущность | Кандидат-источник | Статус |
|---|---|---|
| Pathway (полноценно) | Reactome, KEGG | **не зарегистрирован**, KEGG имеет ограничения лицензии |
| Metabolite | HMDB | **не зарегистрирован** |
| BiologicalSystem / орган | требует онтологии (UBERON?) | **не решено** |
| Временны́е метки взаимодействий | версии DrugBank разных лет | **требует двух релизов**, у нас один |
| PK-параметры (клиренс, AUC) | нет открытого источника | **вероятно недостижимо** |

**Следствие:** temporal split и pathway-голова блокированы. Не планировать их
как гарантированные результаты.

## 7. Что нельзя делать с этими данными

* **Не коммитить** в репозиторий: DrugBank full XML, DDInter, SIDER, BioSNAP,
  TWOSIDES — редистрибуция запрещена или ограничена. Только `data/raw/` под
  `.gitignore` и запись в `DATA_PROVENANCE.md`.
* **Не выводить** биологические связи, которых нет в источнике.
* **Не превращать** текстовые описания в биологические факты без явной
  процедуры маппинга с оценкой достоверности (см. `MECHANISM_ONTOLOGY.md`).
* **Не смешивать** MODEL-INFERRED и EXTERNALLY-SUPPORTED (см. `EVIDENCE_MODEL.md`).
