Generated by `scripts/08_dataset_report.py`. Source file: `data/raw/drugbank.tab.gz`.

## Reconciliation with the stated counts

| Quantity | Stated | Measured | Match |
|---|---|---|---|
| Rows in file | 191,808 | 191,808 | yes |
| Unique drugs | 1,706 | 1,706 | yes |
| Interaction types | 86 | 86 | yes |
| Unique **unordered pairs** | not stated | 191,402 | see below |

**Discrepancy found.** The file has 191,808 rows but only 191,402 unique unordered pairs - a difference of 406.

Cause: 406 unordered pairs are recorded twice with *different* `Y` values. There are **no exact duplicates**. A drug pair can carry more than one documented mechanism at once, so this is a genuine multi-label structure rather than dirty data.

Consequence for the experiments:

- **Binary task** (does this pair interact): use the 191,402 unordered pairs. Counting rows would double-count 406 facts and, worse, could place the two copies of one fact on opposite sides of a split.
- **86-class typing task**: genuinely multi-label for those 406 pairs. `load_pairs()` keeps every type in `y_types` so neither view is lost.

## ⚠ There are no negative examples

`Y` is the interaction **type** (1..86), not a binary label. Every row is a documented interaction. The dataset contains no non-interacting pairs at all, so any binary experiment must generate its own negatives.

Graph density: 191,402 pairs out of 1,454,365 possible = **13.16%**. The remaining 86.84% is *unlabelled*, not negative.

Negative-sampling options and their drawbacks are recorded in `LIMITATIONS.md` (L1.3). **The choice is not made in code yet.**

### Unparseable structures

- **DB11630** — appears in 10 pairs
  - `OC1=CC=CC(=C1)C-1=C2\CCC(=N2)\C(=C2/N\C(\C=C2)=C(/C2=N/C(/C=C2)=C(\C2=CC=C\-1N2)C1=CC(O)=CC=C1)C1=CC(O)=CC=C1)\C1=CC(O)=CC=C1`

This is an upstream defect in the export, not a parsing bug on our side: the SMILES uses malformed ring-closure syntax (`C-1=`, `\-1N2`) which is not valid SMILES. RDKit reports a syntax error at the ring-bond token.

**Decision required before modelling.** A drug with no parseable structure cannot be given ECFP4 features, so it must either be dropped (losing its pairs) or carried with an all-zero feature vector plus a missingness flag. The loader keeps it with `valid=False` and makes no decision. Recorded in `LIMITATIONS.md`.
