## 2. Откуда взялись препараты

Единственный источник — экспорт Therapeutics Data Commons
`tdc.multi_pred.DDI(name='DrugBank')`, файл `data/raw/drugbank.tab.gz`
(PyTDC 1.1.15, загружен 2026-08-24, CC BY-NC 4.0). Шесть колонок:
`ID1, ID2, Y, Map, X1, X2`.

**`Y` — не бинарная метка.** Это тип взаимодействия, целое от 1 до 86. Каждая
из 191 808 сырых строк является задокументированным взаимодействием;
отрицательных примеров в источнике **нет вообще**. Всякий негатив в проекте
сгенерирован нами, и схема генерации — методологическое решение первого класса.

### Расхождение с полной вселенной DrugBank

| | |
|---|---|
| в файле TDC | 1 706 препаратов, 191 402 неупорядоченные пары (191 808 строк) |
| **в экспорте** | **1 705 препаратов, 191 392 пары** |
| исключено | **DB11630**, 10 пар (0.0052 % корпуса) |

Причина исключения: SMILES этого препарата в экспорте TDC содержит
некорректный синтаксис замыкания цикла (`C-1=`, `\-1N2`), RDKit его не
разбирает. Это дефект вышестоящего источника. Исключение выполняет
`drop_unparseable` — оно **видимое и обязательное**, а не тихий фильтр, и
печатается в лог каждого прогона.

Более широкое расхождение: полная база DrugBank содержит порядка 15 000
препаратов и свыше 1.4 млн утверждений о взаимодействиях. Экспорт TDC — её
подмножество, отобранное вышестоящим составителем по неизвестным нам
критериям. **Считать эти 1 705 препаратов представительной выборкой из
DrugBank нельзя.**

| Колонка | Заполнено | Происхождение |

| `rdkit_parseable` | 1705 / 1705 | флаг |

### ⚠ Колонка `name` не содержит названий

`name` — **побайтовая копия `drugbank_id`**. Проверено:
`(drugs.name == drugs.drugbank_id).all()` возвращает `True`. Настоящих названий
препаратов в проекте нет ни в каком виде.

**Следствие для внешнего соединения: сопоставление по названиям невозможно в
принципе.** Код, который выглядит как соединение по именам, на самом деле
сопоставляет номера учётных записей со словами.

### ⚠ Четыре препарата без InChIKey

`DB00515`, `DB00526`, `DB00958`, `DB13145`.

Все четыре — **платиновые координационные комплексы** (цисплатин, оксалиплатин,
карбоплатин и родственное соединение). RDKit их SMILES разбирает: там
донорно-акцепторные связи (`[NH3]->[Pt]`). Но стандартный InChI для
координационных соединений с дативными связями **не определён** — это
ограничение самого InChI, а не дефект данных и не ошибка разбора.

**Любое соединение по InChIKey молча потеряет цисплатин, карбоплатин и
оксалиплатин** — клинически значимые препараты с реальными взаимодействиями.
Для них нужен либо DrugBank ID напрямую, либо отдельная обработка.

## 4. Канонический идентификатор

**`drugbank_id`.** Он и только он заполнен на 100 % и служит ключом узлов во
всём конвейере: `split.py` разделяет по нему, `ddi_graph.py` индексирует по
нему, `negatives.py` выбирает по нему.

`inchikey` — **предпочтительный ключ для внешнего биологического соединения**
(им уже соединяются DrugCentral и ChEMBL), но он неполон, см. выше. Правильный
порядок: `inchikey` как основной ключ, `drugbank_id` как запасной для четырёх
платиновых комплексов.

## 5. Определения сплитов

Три схемы, все реализованы в `src/ddinet/data/split.py`, единая точка входа
`build_any(scheme, drugs, pairs, seed=seed)`.

| Схема | Что делится | Назначение |
|---|---|---|
| `random_pair` | **пары** | **Протекающая. Объект измерения, а не рабочий вариант.** Воспроизводит то, что делает значительная часть литературы по DDI |
| `drug` | препараты | честная; даёт S1/S2/S3 |
| `scaffold` | каркасы Бемиса–Мурко | строже `drug`: близкие аналоги не расходятся по разные стороны |

### S1 / S2 / S3

Определены через членство препаратов относительно обучающего множества
(Pahikkala et al. 2015):

- **S1** — оба препарата пары в обучении;
- **S2** — ровно один вне обучения;
- **S3** — оба вне обучения.

Для `drug` и `scaffold` это **сконструировано**: бакеты так и называются
(`test_S2`, `test_S3`), а бакета `test_S1` не существует — пара из двух
обучающих препаратов и есть обучающая пара.

Для `random_pair` членство не контролируется, поэтому состав S1/S2/S3
**измеряется постфактум**, а бакеты называются просто `train`/`val`/`test`.

### Отбрасываемые пары

В `drug` и `scaffold` пара, один конец которой в валидации, а другой в тесте,
**отбрасывается**, а не назначается. Иначе препарат, на котором подбирали,
всплыл бы в тесте. На сиде 0 отброшено 8 612 пар (`drug`) и 8 211 (`scaffold`).

### Размеры на сиде 0 (полностью — в манифесте, для всех пяти сидов)

| Схема | train / val / test препаратов | Бакеты пар |
|---|---|---|
| `random_pair` | 1691 / 1567 / 1574 (пересекаются) | train 133 974, val 28 709, test 28 709 |
| `drug` | 1195 / 255 / 255 | train 93 630, val_S2 42 076, val_S3 4 729, test_S2 38 466, test_S3 3 879 |
| `scaffold` | 1205 / 276 / 224 | train 94 196, val_S2 44 409, val_S3 5 184, test_S2 35 996, test_S3 3 396 |

Числа препаратов у `random_pair` пересекаются между группами — это не ошибка,
а определяющее свойство схемы: один препарат присутствует и в обучающих, и в
тестовых парах одновременно. Именно поэтому она течёт.

## 6. Сиды

`0, 1, 2, 3, 4` — ровно те, на которых выполнялась сетка Фазы A-2
(`scripts/15_phase_a2_gnn.py`, значение `--seeds` по умолчанию).

Сид управляет **и** разбиением, **и** инициализацией весов, **и** выборкой
негативов. В сетке `split_seed = init_seed = seed`.

## 7. Сплиты не перегенерированы — они воспроизведены и сверены

Сплиты никогда не сохранялись в файлы: сетка вызывает `build_any` внутри
каждого прогона. Функция детерминирована при заданных
`(scheme, drugs, pairs, seed)`, поэтому вызов здесь воспроизводит то же
разбиение, а не создаёт новое.

Что это не предположение, а проверено: `verify_against_results` сверяет
воспроизведённые размеры тестовых бакетов с числом положительных примеров,
записанным сеткой в `reports/phase_a2_results.csv` для каждого прогона.

**Результат сверки: 15 из 15 ячеек совпали, расхождений нет.** При несовпадении
экспорт прерывается: разбиение, не совпадающее с обученным, бесполезно.

### Почему две гранулярности

Для `drug` и `scaffold` назначение препарата определяет всё: бакет пары
следует из её двух концов, а straddle-пара отбрасывается по правилу. Строк
уровня препарата достаточно, и их 17 тысяч вместо миллионов.

Для `random_pair` делятся сами пары, членство препаратов не контролируется, и
описания уровня препарата **не существует**. Поэтому только там нужен
пофазный экспорт, и он вынесен в отдельный сжатый файл.

## 10. Чего в экспорте нет и почему

- **Негативов.** Их нет в источнике и они генерируются на лету из
  `(bucket, strategy, seed)`. Экспортировать их значило бы зафиксировать один
  розыгрыш как канонический.
- **Признаков.** ECFP4, молекулярные графы, граф DDI строятся из SMILES
  детерминированно, воспроизводятся из экспортированного и заняли бы на
  порядки больше места.
- **Биологических аннотаций.** Их в этом корпусе нет. Мишени и пути приходят из
  DrugCentral и Reactome и живут отдельно, в `src/ddinet/adapters/`.
- **Названий препаратов.** Их не существует, см. §3.
