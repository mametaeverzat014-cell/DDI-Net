# AI_USE.md

Лог использования инструментов искусственного интеллекта в проекте DDI-Net.

Файл ведётся для приложения к работе: правила Regeneron ISEF требуют раскрытия
использования генеративного ИИ, а также чёткого разделения того, что сделал
участник, и того, что сделал инструмент.

Последняя ревизия: 2026-08-23.

---

## 1. Констатация

**Первичная кодовая база проекта написана инструментом Claude Code (Anthropic)
в одной сессии 2026-08-23. Объём — 8 544 строки Python в 41 модуле.**

Участник проекта проводит построчную ревизию этого кода. До её завершения
любой модуль следует считать непроверенным (см. `LIMITATIONS.md`, L0.2).

Это не «ИИ помог с отдельными фрагментами». Это «ИИ написал первоначальную
реализацию целиком, а участник её ревизует, переопределяет объём и принимает
решения». Формулировка выбрана намеренно прямой, потому что смягчённая была бы
недостоверной.

---

## 2. Разделение ролей

### Что делал участник

- Поставил научный вопрос: насколько метрики опубликованных DDI-моделей
  завышены из-за утечки данных и сохраняется ли преимущество GNN при честной
  оценке.
- Определил план из трёх фаз, сроки, критерии приёмки.
- Принял решение об источнике данных: Therapeutics Data Commons (`tdc.multi_pred.DDI`),
  отклонив альтернативы.
- Обнаружил и квалифицировал нарушение: сгенерированный ИИ набор данных
  использовался как научный. Распорядился понизить его до тестовой фикстуры,
  аннулировать все посчитанные по нему числа и пометить их явно.
- Принял решение убрать co-attention из Фазы A с обоснованием: в эксперименте
  про утечку должна меняться одна переменная — схема разбиения, а кастомная
  архитектура смешивает два фактора.
- Установил жёсткие правила проекта: никаких синтетических данных, обязательный
  провенанс, фиксированные seed'ы, запрет оптимизации на тесте, ведение
  `LIMITATIONS.md` с самого начала.
- Задал требование раскрытия использования ИИ (этот файл).

### Что делал инструмент

- Написал реализацию: загрузчики и парсеры источников, схемы разбиения,
  сборку датасета, признаки (ECFP4, молекулярные графы, граф взаимодействий),
  модель, цикл обучения, метрики, baselines, кросс-валидацию, харнесс FAERS.
- Написал 127 тестов.
- Написал документацию (`docs/step*.md`, `README.md`, этот файл,
  `DATA_PROVENANCE.md`, `LIMITATIONS.md`).
- **Сгенерировал набор `data/curated/`** — 104 препарата и 467 «взаимодействий»
  из параметрической памяти, без обращения к внешним источникам. См. раздел 4.
- Выполнил чистку и переструктурирование по указаниям участника.

## 4. Главное раскрытие: сгенерированные ИИ «данные»

**Инструмент сгенерировал набор, внешне неотличимый от научных данных, и
поместил его в `data/`.**

Что это было: 104 препарата с названиями, SMILES и аннотациями CYP450, плюс
467 пар взаимодействий с уровнем тяжести и механизмом. Всё — из
параметрической памяти модели, без обращения к DrugBank, PubChem или любому
другому источнику.

Что инструмент сделал правильно: снабдил набор валидацией SMILES по независимо
указанным брутто-формулам (она поймала четыре реальные ошибки в структурах),
пометил его в документации как development fixture и предупредил о
циркулярности меток относительно CYP-признаков.

Что инструмент сделал неправильно: положил его в `data/`, назвал `curated`
(что подразумевает научную курацию), считал по нему метрики и выносил их в
документацию как результаты.

Как исправлено: набор перенесён в `tests/fixtures/synthetic_ddi/`, каждый CSV
несёт в первых строках запрет на расчёт метрик, все посчитанные числа
аннулированы с сохранением исходных файлов (`reports/ANNULLED.md`), в README и
`docs/step*.md` добавлены баннеры.

**Это раскрытие приводится полностью потому, что оно является содержательным
методологическим уроком проекта, а не administrativia.** Правдоподобно
выглядящие сгенерированные данные — реальный режим отказа при работе с ИИ, и
он воспроизводим: набор прошёл внутреннюю валидацию, выглядел
профессионально и был бы принят без вопросов, если бы участник не спросил о
происхождении каждого файла.

## 5. Ошибки инструмента, обнаруженные и исправленные

Перечислено для полноты: код, написанный ИИ, содержал ошибки, и часть из них
была поймана механизмами, которые тот же инструмент и построил.

| Ошибка | Как обнаружена | Статус |
|---|---|---|
| Четыре неверных SMILES (вальпроевая кислота, оксикодон, моксифлоксацин, дигоксин) | Валидация по брутто-формулам | исправлено |
| `collision_rate` считала повторы одной подструктуры коллизиями, завышая показатель примерно на порядок | Ревизия семантики при проверке результата | исправлено |
| Вывод «degree-baseline даёт 0.500 в S2, значит degree-matching работает» — неверен: это артефакт разбиения | Собственный тест инструмента | исправлено, оба факта закреплены тестами |
| Дублирующееся и некорректное списковое включение в `06_faers_validation.py` | Ревизия перед запуском | исправлено |
| Метрики считались и публиковались на сгенерированном наборе | Инвентаризация участником | исправлено |

Последняя строка — самая важная: её поймал человек, а не инструмент.

## 6. Как ИИ используется дальше

Планируемый режим на Фазы A–C:

- **Допустимо:** написание кода по спецификации участника, рефакторинг,
  написание тестов, поиск ошибок, оформление документации.
- **Недопустимо:** генерация любых данных, аннотаций препаратов, значений
  метрик, ссылок на литературу и номеров PMID. Все данные приходят из
  цитируемых источников через `DATA_PROVENANCE.md`.
- **Требует проверки участником:** любое утверждение о фармакологии, любое
  число, любая ссылка.

Каждое существенное использование дополняет раздел 3.
